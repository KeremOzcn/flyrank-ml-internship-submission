Abstract. Content pages lose search visibility over time, but prioritizing which pages to refresh is a manual, reactive process. We frame this as a binary classification task — predicting whether a page's impressions are declining — and build a ranked action engine on top of the model. Using 30,000 pages across 32 pseudonymized clients with 52 engineered features (momentum, traffic, content, and engagement signals), we train five models under client-holdout validation and GroupKFold cross-validation. The best model (LightGBM) achieves ROC AUC 0.995 and Average Precision 0.997 on held-out clients, substantially outperforming the stale-first heuristic baseline (ROC AUC 0.537). The action engine assigns each page a priority score (0–100), a suggested action (refresh, review CTR, expand, protect, monitor), and human-readable reason codes — producing a decision-support queue rather than a black-box prediction.

01 — Introduction

The problem is not which pages declined.
It's which to act on first.

SEO content platforms monitor thousands of pages across dozens of clients. When a page's search impressions decline, the fix is a content refresh — but identifying which pages need attention, and why, is reactive and manual. Content managers drown in dashboards; the question they need answered is simple: what should I work on today?

Research Question

Can we predict, from observable page-level metrics, which content pages are declining in search visibility — and rank them by priority for a refresh action?

Decision Supported

A content manager receives a priority-ranked queue. Each page has a score (0–100), a suggested action (refresh, review CTR, expand, protect, monitor), and human-readable reason codes. This is decision-support, not a causal claim. We observe patterns in historical data. We do not predict Google's algorithm.

Label Source: trend_direction

Derived from comparing impressions_last_30d vs impressions_prev_30d: down if decline exceeds 20%, up if growth exceeds 20%, else stable, flat, or new.

Missingness is systematic

Keyword-context columns (search_volume, competition, cpc) are 100% missing for feedly article rows. provider_used is 71% missing. A blind fillna(0) silently encodes content type into features.

Per-client variation justifies client-aware validation

Declining rates range from 0% to 94% across clients. Page counts range from 3 to 7,008. A random row split would leak client-specific patterns into the test set.

Exclusions

  • trend_direction, trend_pct — label-derived (leakage)
  • content_id, client_id — identifiers (grouping only)
  • provider_used, model_used — not model features
03 — Methodology

52 features. 5 models.
Client-holdout validation.

Label

Binary: is_declining = (trend_direction == "down") — 54.2% positive rate. Also tested 3-class and regression formulations; binary gives the clearest decision boundary for the action engine.

Feature Engineering

  • Momentum: impression / click / session momentum (last30 / prev30 ratio, clipped 0–10)
  • Ratios: CTR×impressions, engagement×sessions, scroll×CTR, position×impressions, impressions/day, clicks/impression, engaged session rate, AI session share
  • Traffic (log): log-impressions, log-clicks, log-sessions, log-pageviews, log-AI sessions, log-scroll events, log-users
  • Rates: CTR, avg position, engagement rate, scroll rate, AI traffic %
  • Content: word count, char count, content age, days since update, search volume, competition, CPC
  • Flags: is_stale (>90d), is_very_stale (>180d), has_been_updated, has_position, is_top10, is_top3, has_clicks, has_ai_sessions, measurable_opportunity
  • Categorical (9): competition_level, content_type, main_intent, age_tier, freshness_tier, word_count_tier, char_count_tier, impression_tier, position_tier
Leakage check passed. No feature contains trend or decline. Label-derived columns excluded programmatically. Verified in capstone_feature_config.json.

Baselines

  • Majority class — always predict "not declining" (ROC AUC = 0.500)
  • Random — uniform random probabilities
  • Stale-first rule — rank by content age + staleness flags (existing heuristic)

Models

  • Logistic Regression — linear baseline, balanced, standardized
  • Random Forest — 300 trees, depth 12, balanced subsample
  • XGBoost — 300 trees, depth 6, lr 0.1, subsample 0.8
  • LightGBM — 300 trees, depth 8, lr 0.1, balanced
  • Extra Trees — 300 trees, depth 12, balanced

Validation

  • Primary split: Client-holdout — 26 clients train (25,277 pages), 6 clients test (4,723 pages)
  • Cross-validation: 5-fold GroupKFold (grouped by client) for out-of-client stability
  • Seed: 42 — all results reproducible

Per-Client Performance

Error Analysis

97 false negatives, 50 false positives (error rate 3.1%). False negatives concentrate among low-traffic pages (<100 impressions) where signal is weakest. False positives cluster around high-traffic stable pages — the model is slightly over-sensitive to volume changes.

05 — Limitations

What this work cannot claim.

  • Teaching slice, not full warehouse. 30K rows, not 79M. Pipeline is designed to scale via DuckDB + hf://, but results reflect the slice only.
  • Label is retrospective. The label measures whether a page already declined. The model identifies declining pages, not predicts future declines.
  • Momentum dominates. impression_momentum carries 63% of importance. The model detects decline, not leading indicators. The action engine's value is prioritization, not early warning.
  • No causal claims. Refreshing a page may or may not reverse decline. The model says which pages are declining and why — not that a refresh will fix it.
  • 32 clients, not 104. Cross-client generalization tested on 6 held-out clients. Sufficient for capstone; not production.
  • Rate columns are ×100 percentages. CTR = 0.76 means 0.76%, not 76%.
  • Position = 0 means no data. 1,205 rows. Flagged with has_position.
